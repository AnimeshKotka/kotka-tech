## Launch Templates and Tenancy

- A <Tag color="#ffb347">launch template</Tag> specifies instance configuration (AMI ID, instance type, key pair, security groups, etc.).
- Default tenancy: <Tag color="#f08080">shared</Tag>.
- Tenancy behavior:
  - Launch Template: `shared`, VPC: `dedicated` → <Tag color="#90ee90">dedicated tenancy</Tag>
  - Launch Template: `dedicated`, VPC: `default` → <Tag color="#90ee90">dedicated tenancy</Tag>

---

## EC2 Tenancy Options

- By default, <Tag color="#ffb347">Amazon EC2</Tag> instances run on <Tag color="#f08080">shared tenancy</Tag>.
- <Tag color="#ffb347">Dedicated Instances</Tag>:
  - Run on hardware dedicated to one customer.
  - Isolated across AWS accounts but can share hardware across instances within same account.
- <Tag color="#ffb347">Dedicated Hosts</Tag>:
  - Full control over instance placement.
  - Visibility into physical server.

## EC2 Spot Instances

- <Tag color="#ffb347">Spot Instance</Tag> = unused EC2 at reduced price.
- Pricing is determined by long-term demand/supply in each AZ.
- Spot Instance request types:
  - <Tag color="YELLOW">One-time</Tag>
  - <Tag color="PINK">Persistent</Tag>
- <Tag color="#87cefa">Persistent</Tag> requests reopen after interruption.
  - Spot Fleets maintain target capacity by launching replacements.
  - Canceling requests:
    - May or may not terminate instance depending on config.

---

## EC2 Recovery

- <Tag color="#ffb347">Recover impaired EC2 instance</Tag> using <Tag color="#87cefa">CloudWatch alarms</Tag>.
- Recovery applies to hardware failure or AWS-repairable issues.
- Preserves:
  - Instance ID
  - Private & Elastic IPs
  - Metadata
- If instance is in a placement group, recovery remains within group.
- <Tag color="#f08080">Note:</Tag> Data in memory is lost.

## 🧠 Amazon EBS Volume Types — Memorize Like a Pro

### ✅ <Tag color="#1e90ff">Provisioned IOPS SSD (io1)</Tag> — **Best for High IOPS Needs**

- **Backed by**: SSD (Solid-State Drives)
- **Use Case**: <Tag color="#ffa500">Mission-critical, I/O-intensive workloads</Tag> (e.g., production-grade **databases**)
- **IOPS Performance**:  
  - **Up to 50 IOPS/GB**
  - <Tag color="#ffa500">Max 64,000 IOPS per volume</Tag>
- **Throughput**: Up to **1,000 MB/s** per volume
- **Why Choose**: <Tag color="#32cd32"><strong>Meets use-case needing 25,000 IOPS</strong></Tag>

---

### ❌ Incorrect Choices (Not suitable for high IOPS needs)

#### 🟡 <Tag color="#1e90ff">General Purpose SSD (gp2)</Tag> — **Balanced for General Use**

- **Backed by**: SSD  
- **Use Case**: Dev/Test, Boot volumes, Web servers  
- **Max IOPS**: <Tag color="#ffa500">16,000 IOPS</Tag> (not sufficient for 25k+)
- **Throughput**: Moderate  
- 🧠 *Good all-rounder, but not built for intense workloads*

---

#### 🔵 <Tag color="#1e90ff">Cold HDD (sc1)</Tag> — **For Archival Storage**

- **Backed by**: HDD (Hard Disk Drive)
- **Use Case**: Infrequently accessed, cold datasets
- **Max IOPS**: <Tag color="#ffa500">250 IOPS</Tag>
- **Throughput**: Low  
- 🧠 *Think: Cheap, cold storage for backups*

---

#### 🟣 <Tag color="#1e90ff">Throughput Optimized HDD (st1)</Tag> — **For Big, Streaming Data**

- **Backed by**: HDD  
- **Use Case**: <Tag color="#ffa500">Throughput-intensive workloads</Tag> (e.g., MapReduce, Kafka, ETL, log processing)
- **Max IOPS**: <Tag color="#ffa500">500 IOPS</Tag>
- **Throughput**: High  
- 🧠 *Great for throughput, bad for high IOPS*

---

### 🔑 Summary Table

| Volume Type | Backed By | Max IOPS | Best For |
|-------------|------------|-----------|------------|
| <strong>io1</strong> | SSD | <Tag color="#32cd32">64,000</Tag> | <Tag color="#ffa500">High IOPS DBs</Tag> |
| gp2         | SSD | 16,000 | Dev/Test |
| st1         | HDD | 500     | Big data streaming |
| sc1         | HDD | 250     | Archival |

## FSx for Lustre

- Use <Tag color="#ffb347">FSx for Lustre</Tag> with <Tag color="#f08080">Scratch File System</Tag> for:
  - Temporary storage
  - Short-term data processing
- No replication, non-persistent if a file server fails.
- Up to 6× burst throughput of baseline 200 MBps/TiB.

---

## Amazon Redshift

- <Tag color="#ffb347">Amazon Redshift</Tag> is a fully managed <Tag color="RED">petabyte-scale data warehouse</Tag> in the cloud.
- Can be a target for data migration from other databases.

---

## Route 53: Alias vs CNAME

- <Tag color="#ffb347">Amazon Route 53</Tag>:
  - <Tag color="BLUE">No charge for alias queries</Tag>, but charges for CNAME.
  - Alias → AWS resources only (S3, CloudFront, same hosted zone).
  - CNAME → Any DNS record.
- At zone apex (`covid19survey.com`):
  - <Tag color="#fa8072">Cannot create CNAME</Tag>
  - <Tag color="#90ee90">Can create alias</Tag> (e.g., point to `www.covid19survey.com`)

---

## Internet Gateway

- <Tag color="#ffb347">Internet Gateway</Tag>:
  - Acts as route target for internet-bound traffic.
  - Performs <Tag color="BLUE">network address translation (NAT)</Tag> for public IPv4 instances.

---

## Amazon SQS Polling

- <Tag color="#ffb347">Amazon SQS</Tag> supports:
  - <Tag color="#87cefa">Short polling</Tag>: immediate response, may be empty.
  - <Tag color="#90ee90">Long polling</Tag>: waits for messages up to a timeout.
<br/><br/><Tag color="BLUE">Long polling makes it inexpensive</Tag> to retrieve messages, reducing cost and empty receives.

---

## Amazon SQS FIFO Throughput

- By default, <Tag color="#ffb347">FIFO queues</Tag> support up to <Tag color="#90ee90">3,000 messages/sec</Tag> with batching.
- Without batching: up to <Tag color="#f08080">300 messages/sec</Tag> (send, receive, or delete operations).
- <Tag color="BLUE">Batching</Tag> enables meeting higher throughput requirements (up to 3,000 messages/sec).


## AWS CloudFormation StackSets

- <Tag color="#ffb347">StackSet</Tag> = CloudFormation + multi-account + multi-region.
- Uses one template from admin account.
- Provisions into target accounts/org units across regions.

---

## Elastic Load Balancer: Connection Draining

- <Tag color="#ffb347">Elastic Load Balancing</Tag>:
  - Uses <Tag color="BLUE">connection draining</Tag> for:
    - De-registering or unhealthy instances.
    - Preserves existing connections until timeout (1–3600s, default: 300s).
  - After timeout, force-closes remaining connections.

---

## DynamoDB Global Tables

- <Tag color="BLUE">Active-active configuration</Tag> in <Tag color="#ffb347">DynamoDB global tables</Tag>:
  - No failover – data is written regionally and replicated.
  - More expensive than Aurora Global Database.

---

## VPC Sharing

- <Tag color="#ffb347">VPC sharing</Tag> via <Tag color="#87cefa">Resource Access Manager (RAM)</Tag>:
  - Allows multiple accounts to deploy resources in a shared VPC.
  - Owner shares <Tag color="GREEN">subnets</Tag> (not VPC itself) with org participants.

---

## Elastic Fabric Adapter (EFA)

- <Tag color="RED">Elastic Fabric Adapter (EFA)</Tag>:
  - Enhances <Tag color="#90ee90">HPC</Tag> and <Tag color="#90ee90">ML</Tag> inter-instance communication.
  - Adds OS-bypass interface to ENA features.
  - User-space apps can access transport directly for performance.

## Elastic Cache
- <Tag color="#90ee90">Amazon ElastiCache</Tag> can be used to significantly improve latency and throughput for many read-heavy application workloads
  (such as social networking, gaming, media sharing, leaderboard, and Q&A portals) or <Tag color="RED">compute-intensive workloads</Tag> (such as a recommendation engine) by allowing you to store the objects that are often read in the cache.
