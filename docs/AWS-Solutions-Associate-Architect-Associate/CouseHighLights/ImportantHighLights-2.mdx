## Secrets Management

- <Tag color="#ffb347">AWS Secrets Manager</Tag> helps you protect secrets needed to access your applications, services, and IT resources.
  - Enables easy rotation, management, and retrieval of database credentials, API keys, and other secrets.
  - Applications can retrieve secrets via <Tag color="#ffb347">Secrets Manager APIs</Tag>, removing the need to hardcode secrets.
  - Offers secret rotation with <Tag color="#87cefa">Amazon RDS</Tag>, <Tag color="#87cefa">Amazon Redshift</Tag>, and <Tag color="#87cefa">Amazon DocumentDB</Tag>.
  - <Tag color="#fa8072">Note:</Tag> <Tag color="#f08080">KMS</Tag> is an encryption service, <Tag color="#fa8072">not a secrets store</Tag>.

## Auto Scaling Group (ASG) Behavior

- <Tag color="#ffb347">Auto Scaling Group</Tag> is not terminating an unhealthy <Tag color="#87cefa">Amazon EC2</Tag> instance:
  - Instance may be in <Tag color="#f4a460">Impaired</Tag> status.
  - The health check <Tag color="#f08080">grace period</Tag> has not yet expired.
  - Instance has failed the <Tag color="#87cefa">ELB</Tag> health check.

## Amazon RDS

- <Tag color="#ffb347">Read Replicas</Tag> are used for <Tag color="#90ee90">scalability</Tag> (not availability).
  ![Amazon RDS RR](../../../static/assets/pt2-q8-i1.jpg)

- <Tag color="#ffb347">DB Snapshots</Tag> are stored in an <Tag color="#87cefa">S3 bucket</Tag> in the same region.
  - No direct access is granted to these snapshots.

- <Tag color="#ffb347">Billing:</Tag>
  - Read replicas are billed as standard DB instances.
  - No charges for intra-region replication traffic.

## DNS Settings for Private Hosted Zones

<Tag color="#ffb347">DNS hostnames</Tag> and <Tag color="#ffb347">DNS resolution</Tag> are required for private hosted zones to function.

### DNS Hostnames

- Disabled by default in non-default VPCs.
- Must be enabled to use private hosted zones.

### DNS Resolution

- Works only with the <Tag color="#87cefa">VPC DNS server</Tag> (reserved IP: base of VPC IPv4 + 2).
- Enable only if using <Tag color="#87cefa">private hosted zones</Tag>, not if using custom DNS servers via DHCP options.

## EC2 User Data Scripts

- Scripts run as <Tag color="#f08080">root</Tag> (no need for `sudo`).
- Files are owned by root.
- Adjust permissions for non-root access.

## Placement Groups in EC2

### <Tag color="#ffb347">Cluster Placement Group</Tag>

- Packs instances in one AZ for <Tag color="#90ee90">low-latency</Tag>.
- Best for <Tag color="#87cefa">HPC</Tag> workloads.
- Not for distributed workloads like <Tag color="#f4a460">Hadoop</Tag>.

### <Tag color="#ffb347">Partition Placement Group</Tag>

- Spreads across partitions with separate hardware.
- Ideal for <Tag color="#90ee90">distributed, replicated systems</Tag> like <Tag color="#f4a460">Kafka</Tag>, <Tag color="#f4a460">Hadoop</Tag>, <Tag color="#f4a460">Cassandra</Tag>.

### <Tag color="#ffb347">Spread Placement Group</Tag>

- Spreads a few instances across distinct hardware.
- Reduces correlated failure risk.
- Not for distributed workloads like Hadoop.

## Amazon Kinesis & Firehose

- With <Tag color="#ffb347">Kinesis Data Stream</Tag> as the source for <Tag color="#87cefa">Kinesis Firehose</Tag>:
  - Firehose's `PutRecord` and `PutRecordBatch` are <Tag color="#fa8072">disabled</Tag>.
  - <Tag color="#f08080">Kinesis Agent</Tag> cannot write directly to Firehose.
  - Use <Tag color="#87cefa">Kinesis Data Streams</Tag> `PutRecord` and `PutRecords` APIs.

## AWS Transit Gateway & Shared Services Architecture

- In a <Tag color="#87cefa">hub-and-spoke</Tag> architecture, <Tag color="#ffb347">Transit Gateway</Tag> connects VPCs across accounts.
- A <Tag color="#f08080">Shared Services VPC</Tag> centralizes services like:
  - <Tag color="#87cefa">Directory Services</Tag>
  - <Tag color="#87cefa">VPC Endpoints</Tag>

<Tag color="#90ee90">Benefits:</Tag>
- Reduces duplication and admin overhead.
- Centralized control and cost efficiency.
